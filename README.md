# Study Log

個人用の学習記録アプリ（PWA）です。

## パソコンで動かす

1. このフォルダで PowerShell を開く
2. `python -m http.server 8123` を実行する
3. ブラウザで <http://localhost:8123/> を開く
4. 終了するときは PowerShell で `Ctrl + C` を押す

## アプリを更新するとき（重要）

ファイルを変更して公開するときは、次の2か所の番号を**同じ新しい番号**に変えてください。

1. `js/app.js` の `APP_VERSION`
2. `service-worker.js` の `CACHE_VERSION`

番号を変えると、利用中の端末に「新しいバージョンがあります」と表示され、「更新する」を押すと最新になります。番号を変えないと、端末には古い内容が残り続けます。

ファイルを新しく追加したときは、`service-worker.js` の `FILES` の一覧にも追加してください。

## 公開のしかた（GitHub Pages）

初回だけ行う設定です。

1. GitHub で新しいリポジトリを作る（種類は **Public**、README などは追加しない）
2. このフォルダの内容をアップロードする（Git で push する、またはブラウザの「Add file → Upload files」）
3. リポジトリの **Settings → Pages** を開く
4. 「Source」を **Deploy from a branch**、「Branch」を **main** と **/(root)** にして **Save** を押す
5. 1〜2分待つと、同じ画面の上部に公開URL（`https://ユーザー名.github.io/リポジトリ名/`）が表示される

更新するときは、バージョン番号を2か所変えてから（上の「アプリを更新するとき」）、もう一度アップロードします。

```
git add -A
git commit -m "変更内容のメモ"
git push
```

### うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 公開URLが 404 になる | Settings → Pages の Branch が `main` と `/(root)` か。リポジトリが Public か。`index.html` がリポジトリの一番上にあるか。公開直後は数分待つ |
| 画面は出るがデザインが崩れる | ファイル名の大文字・小文字が、`index.html` に書いた名前と一致しているか |
| 更新したのに変わらない | バージョン番号を2か所とも変えたか。リポジトリの Actions タブで公開処理が終わっているか |
| どうしても古いままになる（パソコン） | `F12` → Application → Service workers の **Unregister**、Storage の **Clear site data** を押して再読み込み（学習記録も消えるので、先にバックアップ） |
| どうしても古いままになる（iPhone） | アプリを完全に閉じて開き直す。直らなければ、バックアップを保存してからホーム画面のアプリを削除し、追加し直す |

## iPhone に入れる（ホーム画面に追加）

1. iPhone の **Safari** で <https://fully815.github.io/sl-mp6qtp9xxt/> を開く（Chrome などではなく Safari を使う）
2. 画面下の **共有ボタン**（四角から上向きの矢印）を押す
3. メニューを下へ送り、**「ホーム画面に追加」** を押す
4. 名前（「Study Log」）を確認し、右上の **「追加」** を押す
5. ホーム画面にできたアイコンから開く

### 知っておくこと

- **記録の保存場所**：学習記録は、ホーム画面のアプリの中に保存されます。Safari で開いたときの記録とは別物です。ふだんはホーム画面のアプリだけを使ってください。
- **オフライン**：ホーム画面のアプリを一度、電波のある場所で開いておくと、次からは電波がなくても起動できます。
- **更新**：新しい版を公開すると、アプリを開いたときに「新しいバージョンがあります」と表示されます。「更新する」を押すと最新になります。記録は消えません。
- **バックアップ**：ホーム画面のアプリを削除すると、記録も消えます。「設定」→「バックアップを保存」で、ときどきファイルに残してください。機種変更のときも、このファイルから復元します。
- **削除**：アイコンを長押しして「ブックマークを削除」（または「App を削除」）を選びます。

### iPhone でうまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「ホーム画面に追加」が見つからない | Safari で開いているか。共有メニューを一番下まで送り、「アクションを編集」から追加できる |
| 開くと Safari のアドレスバーが出る | ホーム画面のアイコンから開いているか。直らなければ、アイコンを削除して追加し直す |
| 記録が消えた・0 に戻った | Safari とホーム画面のアプリで記録は別。開いている場所を確認する |
| 電波がないと開けない | 電波のある場所で一度開き、数秒待ってから閉じる |
| 更新の案内が出ない | アプリを完全に閉じて開き直す（画面下から上へスワイプして、アプリの画面を上へ払う） |

## パソコンでオフライン動作を試すとき

パソコンで開いているとき（localhost）は、変更がすぐ反映されるよう、オフライン用の保存機能を止めています。試したいときだけ、URLの最後に `?pwa=1` を付けて開きます。

<http://localhost:8123/?pwa=1>

元に戻すには、`?pwa=1` を付けずに開き直します（保存分は自動で消えます）。

## データの保存先

学習履歴と設定は、使っている端末のブラウザ内（localStorage）だけに保存されます。外部へは送信しません。

## 苦手度の計算方法

分野ごとに 0〜100 の「苦手度」を計算し、大きい順に苦手分野として表示します。

苦手度 ＝（正答率の低さ × 45 ＋ 回答の遅さ × 20 ＋ 直近の誤答率 × 20 ＋ くり返し誤答 × 10 ＋ 難易度の補正 × 5）× 信頼度

| 要素 | 内容 |
|---|---|
| 正答率の低さ | 1 −（補正した正答率）。補正した正答率 ＝（正解数 ＋ 4 × 全体の正答率）÷（回答数 ＋ 4） |
| 回答の遅さ | 「回答時間 ÷ 目標時間」の平均が1倍なら0、2倍以上なら1 |
| 直近の誤答率 | その分野の最近5回のうち、不正解だった割合 |
| くり返し誤答 | 回答した問題のうち、2回以上間違えた問題の割合 |
| 難易度の補正 | やさしい問題での誤答ほど重く数える |
| 信頼度 | 回答数 ÷ 8（上限1）。回答が少ない分野は苦手度が小さくなる |

回答数が5回未満の分野は「データ不足」として苦手分野に入れません。苦手度が15以上の分野を苦手分野として表示します。数値は `js/analytics.js` の先頭付近で変更できます。
